1. Visão geral do projeto

O togag é um criador de jogos com inteligência artificial baseado na stack Google. O módulo documentado aqui é uma adição completamente nova: uma página de experiência interativa acessível em /video, que permite ao usuário descrever verbalmente ou por texto o jogo que deseja criar, enquanto a IA gera o jogo em tempo real com animações de fundo.

ℹ️
Escopo da implementação: O módulo é completamente independente do editor de jogos existente (/editor). Ele se integra ao fluxo como uma tela de entrada, podendo substituir ou complementar o catálogo.

3. Arquitetura — FSM (Finite State Machine)

A experiência é controlada por uma máquina de estados finita que garante que só transições válidas sejam executadas, evitando estados inconsistentes na UI.

IDLE ──▶ WELCOME ──▶ INTRO ──▶ CONVERSA

┌── loop de perguntas ──┐
CONVERSA ──▶ CONVERSA ──▶ GERANDO ──▶ FINAL ──▶ IDLE
EstadoO que acontecePróximos válidos
IDLEEstado inicial, antes de qualquer interaçãoWELCOME
WELCOMETela de boas-vindas visível; storyTree carregadoINTRO
INTROCanvas de intro animado; narração da IACONVERSA
CONVERSAChat aberto; usuário responde às perguntasCONVERSA, GERANDO
GERANDOCanvas "gerando" + stream de eventos da IAFINAL
FINALJogo pronto; botões "Jogar" e "Recomeçar"IDLE
const FSM = (() => {
  const T = {
    IDLE:     ['WELCOME'],
    WELCOME:  ['INTRO'],
    INTRO:    ['CONVERSA'],
    CONVERSA: ['CONVERSA', 'GERANDO'],
    GERANDO:  ['FINAL'],
    FINAL:    ['IDLE'],
  };
  function ir(prox) {
    if (!(T[estado] || []).includes(prox)) {
      console.warn(`[FSM] inválido: ${estado} → ${prox}`); return false;
    }
    estado = prox; emit('mudanca', { de: anterior, para: prox });
    return true;
  }
  return { ir, on, atual: () => estado };
})();

4. Double Buffering

O Double Buffer mantém dois slots de canvas no DOM (#buffer-a e #buffer-b). Enquanto um está visível ao usuário, o outro é preparado em segundo plano. O swap é feito com uma transição CSS de 260ms, eliminando tela preta entre cenas.

SlotClasses CSSPapel
#buffer-a.visivel (opacity: 1)Cena atual, visível ao usuário
#buffer-b.oculto (opacity: 0)Próxima cena sendo preparada
// Swap: standby se torna visível, ativo some
function trocar(ms = 280) {
  const prox = ativoId === 'A' ? 'B' : 'A';
  slots[prox].classList.remove('oculto');  slots[prox].classList.add('visivel');
  slots[ativoId].classList.remove('visivel'); slots[ativoId].classList.add('oculto');
  ativoId = prox;
}
💡
WeakMap por canvas: Cada canvas tem seu próprio requestAnimationFrame ID armazenado num WeakMap. Isso permite que dois canvases animem em paralelo sem cancelar um ao outro, essencial para o crossfade suave.

5. Canvas Renderer — animações no lugar de vídeos

Em vez de vídeos .mp4 reais (que precisariam de arquivos de asset), cada cena é um animação procedural desenhada pela Canvas 2D API. Isso torna a experiência completamente auto-contida, sem assets externos.

Tipo de cenaEstado FSMO que renderiza
introINTRO Gradiente radial dinâmico + 55 partículas flutuantes + anéis pulsantes + ícone 🤖 + logo togag
conversaCONVERSA Fundo escuro + 4 orbs de luz coloridos flutuando + grid de pontos com parallax
gerandoGERANDO 5 anéis rotativos sobrepostos + 40 partículas orbitando + ícone ⚙️ pulsando + texto de status atualizado em tempo real
finalFINAL Estrelas cintilantes + troféu 🏆 com efeito de escala pulsante
🎨
Resolução DPI: Todos os canvases usam canvas.width = elemento.width × devicePixelRatio com ctx.setTransform(dpr, 0, 0, dpr, 0, 0) para nitidez total em telas Retina/HiDPI.

6. ConversationEngine — conversa livre com IA

Substitui a árvore de decisão com opções fixas por um fluxo conversacional aberto. A IA faz perguntas abertas e o usuário responde com qualquer texto ou fala.

function promptParaGeracao() {
  let p = respostas.descricao || 'crie um jogo legal';
  if (respostas.detalhes) p += '. Detalhes extras: ' + respostas.detalhes;
  return p;

7. VoiceInput — entrada por voz

O usuário pode clicar no botão 🎤 para gravar sua resposta em vez de digitar. O áudio é capturado via MediaRecorder e enviado ao endpoint POST /api/transcrever (já existente no togag, usa Gemini para transcrição).

1

Permissão de microfone

navigator.mediaDevices.getUserMedia({ audio: true }) — solicita acesso ao mic do usuário.

2

Gravação com MediaRecorder

Chunks de 100ms são coletados. Formato preferido: audio/webm;codecs=opus com fallback.

3

Envio para transcrição

O Blob é convertido para Base64 e enviado como JSON para POST /api/transcrever.

4

Preenchimento automático

O texto transcrito preenche o textarea automaticamente, pronto para revisão e envio.

⚠️
Dependência de GCP: O endpoint /api/transcrever usa o Gemini para transcrição. Sem credenciais GCP válidas, a transcrição falhará graciosamente — o usuário ainda pode digitar normalmente.

8. GeneratorEngine — geração de jogos em tempo real

Após coletar as respostas do usuário, o GeneratorEngine cria um projeto e inicia a geração do jogo via streaming NDJSON, exatamente como o editor existente faz.

Fluxo de geração

// 1. Cria o projeto
POST /api/projeto
← { projetoId: "pABC12345" }

// 2. Inicia geração (stream NDJSON)
POST /api/chat/pABC12345
← { "tipo": "status", "texto": "Analisando o pedido..." }
← { "tipo": "passo", "ferramenta": "write_file", "path": "main.js" }
← { "tipo": "passo", "etapa": "Testando o jogo" }
← { "tipo": "concluido", "resumo": "Jogo de plataforma criado com sucesso!" }

Eventos tratados

Tipo de eventoO que o frontend faz
statusAdiciona linha de log no chat + atualiza texto do canvas "gerando"
passoMostra nome da ferramenta/etapa como evento no chat
concluidoTransita para estado FINAL, exibe tela de jogo pronto
erroExibe mensagem de erro, retorna ao estado CONVERSA após 3s
async function* gerarJogo(pedido) {
  const resp = await fetch(`/api/chat/${projetoId}`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ pedido }),
  });
  // Lê o stream NDJSON linha por linha com ReadableStream
  const reader = resp.body.getReader();
  const dec = new TextDecoder();
  let buf = '';
  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    buf += dec.decode(value, { stream: true });
    for (const linha of buf.split('\n').slice(0, -1)) {
      try { yield JSON.parse(linha); } catch {}
    }
  }
}

A gravação começa automaticamente quando a experiência inicia. O usuário pode clicar em "⬇ Exportar" para baixar o WebM com a sessão completa.

Fallbackvideo/webm;codecs=vp8,opus → video/webm
ChunksA cada 100ms
DownloadBlob URL → <a> virtual → click()
Nome do arquivotogag-{timestamp}.webm
ℹ️
O plano original previa conversão para MP4 com H.264 via ffmpeg-static no servidor. Por ora, o download é em WebM (suportado em Chrome, Firefox, Edge). Para converter para MP4, adicione ffmpeg-static ao package.json e implemente o endpoint POST /api/video-export documentado no implementation_plan.md.

10. Fluxo completo da experiência

1

Tela de boas-vindas (estado: IDLE → WELCOME)

Partículas animadas. Usuário clica "Começar a criar" — destrava política de autoplay de áudio.

2

Animação de intro (estado: INTRO)

Canvas com partículas e anel pulsante. IA fala: "Bem-vindo ao togag...". Gravação WebM inicia.

3

Conversa — pergunta 1 (estado: CONVERSA)

Swap para canvas de conversa. IA digita... aparece balão: "Que tipo de jogo você quer criar?"

4

Usuário responde (texto ou voz)

Digita livremente + Enter, ou clica 🎤 → fala → transcrição automática → confirmação → envio.

5

Conversa — pergunta 2 (estado: CONVERSA)

IA pergunta por detalhes. Botão "Pular →" disponível para esta etapa opcional.

6

Geração (estado: GERANDO)

Swap para canvas com anéis rotativos. Cria projeto via API. Stream NDJSON inicia.

7

Eventos em tempo real

Cada passo da IA (lendo arquivo, escrevendo código, testando) aparece como linha de log no chat.

8

Jogo pronto (estado: FINAL)

Swap para canvas de estrelas. Tela final com "▶ Jogar agora" → redireciona para /jogar?id=...
